# 新コース検討：カタカナ語コース／基本漢字コース

Kohei 提案（2026-08-01）を受けた検討資料。**この文書の時点では実装していない。**
着手の可否・順序・設計の選択は §7 の「決めてほしいこと」で判断する。

---

## 1. 結論

**両方とも作る価値がある。ただし着手は「カタカナ語 → 漢字」の順を推奨する。**

理由は費用が一桁違うため。カタカナ語は**既存データからの抽出だけ**で作れる（新しいデータ取得もライセンス確認も不要）。
漢字は価値が最も大きいが、新しいデータ源と「何をもって覚えたとするか」の設計判断が要る。

先に小さいほうを出してメンバーの反応を見てから、漢字の設計に入るのが安全。

---

## 2. 学習パスの中での位置づけ

```
ja-kana（かな208字）
   ↓  文字が読める
【新】カタカナ語（英語由来の語で「読む速さ」を作る）   ← 追加案A
   ↓
ja-0-3k（日常語3,075語） ←→ 【新】基本漢字（N5+N4 約284字）   ← 追加案B
   ↓                              （並行して進める想定）
ja-3-10k → ja-10-23k
```

カタカナ語は**かなと語彙の橋渡し**、漢字は**語彙と並走する別軸**。どちらも既存コースを置き換えない。

---

## 3. 追加案A：カタカナ語コース

### 3.1 なぜ効くか

- カタカナ語の大半は英語由来。**フィリピンチームは意味をほぼ推測できる**ので、学習が
  「意味を覚える」ではなく**「カタカナを速く読む」**に集中できる
- かなを一通り覚えた人でも、カタカナを流暢に読むのは別の壁。そこだけを短期間で潰せる
- 職場・生活で頻出（メニュー・パソコン・エレベーター…）

### 3.2 データ（実測済み）

既存コースから抽出できる。**新しいデータ取得もライセンス追加も不要。**

| 抽出元 | カタカナ語 | うち例文つき |
|---|---|---|
| ja-0-3k | 206語 | 205語 |
| ja-3-10k | 624語 | 546語 |
| 合計 | **830語** | **751語** |

しかも**訳は既にタガログ語**（テレビ→telebisyon、パン→tinapay、ニュース→balita）で、
頻度順位・JLPTレベル・例文もそのまま流用できる。

### 3.3 規模の選択肢

| 案 | 語数 | 向く相手 |
|---|---|---|
| A-1 | 約200語（0-3k帯のみ） | 入門直後。1〜2週間で完走でき達成感が出る |
| A-2 | **約830語（0-10k帯）** | 実用重視。職場で見る語をほぼ網羅（推奨） |
| A-3 | 3,000語超（10k帯も含む） | 過剰。専門語が増えて完走率が落ちる（非推奨） |

### 3.4 カードの作り

既存コースと同じ形をそのまま使う（**エンジン側の改修ゼロ**）。

- 見出し語＝カタカナ語（例「エレベーター」）
- 読み＝そのまま／グロス＝タガログ語（既存の値を流用）
- 例文＝既存の例文を流用

### 3.5 工数

**小。** 抽出スクリプト1本（`pipeline/build_ja_katakana.py`）＋コース登録＋目視確認。

## 4. 追加案B：基本漢字コース

### 4.1 なぜ効くか

- 日本語学習の最大の壁。語彙コースは漢字で書かれた語を出すが、**字そのものは教えていない**
- JLPT に級ごとの漢字要件があり、**既にあるJLPTバッジの動機付けに直結**する
- 規模が約284字（N5+N4）で、ja-kana（208枚）と同程度＝**今のエンジンにそのまま乗る**

### 4.2 データ源（いずれも既に採用済みのライセンス）

| 用途 | データ源 | ライセンス | 備考 |
|---|---|---|---|
| どの字を入れるか | tanos.co.uk の JLPT 漢字リスト | CC BY | **語彙リストで既に採用済み**。同じ出典表記を流用できる |
| 読み（音・訓）・意味 | KANJIDIC2 | EDRDG | JMdict と同じ提供元。**既に EDRDG 表記あり** |
| 例語 | 既存の ja-0-3k / ja-3-10k | 取得済み | その字を使う既習語を1〜2語引く＝学習が繋がる |

新規に契約・取得が必要なものは無い。

### 4.3 規模

| レベル | 字数（目安） |
|---|---|
| N5 | 約103字 |
| N4 | 約181字 |
| **合計** | **約284字** |

※ 実際の字数は tanos のリストを取得した時点で確定させる（上記は一般に流通している目安）。

### 4.4 ⚠️ 決めるべき最重要点：「覚えた」の定義

漢字は語彙カードと違い、**1枚のカードに複数の情報**（意味・音読み・訓読み・使用例）が乗る。
「I know」を押す基準を決めないとカードが設計できない。

| 案 | カードの中身 | 覚えたの基準 | 長所 / 短所 |
|---|---|---|---|
| **B-1 意味だけ** | 山 → bundok (mountain) | 意味が言える | 最速で回る。読めないので語彙学習には直結しにくい |
| **B-2 意味＋代表読み**（推奨） | 山 → bundok / やま・サン | 意味と主な読みが言える | 語彙コースと噛み合う。1枚の情報量が適度 |
| **B-3 意味＋読み＋使用例** | 山 → bundok / やま・サン / 山（やま）, 火山（かざん） | 例語まで言える | 最も実戦的だが1枚が重く、完走率が落ちる恐れ |

**推奨は B-2。** 例語は「めくった面に参考として出すが採点対象にはしない」形にすれば、
B-3 の利点を取り込みつつ1枚を軽く保てる。

### 4.5 工数

**中。** 新規パイプライン（tanos リスト取得＋KANJIDIC2 パース＋例語の紐付け）＋
コース種別の追加＋出典表記＋目視確認。データ生成そのものは自動化できるので、
上の設計判断さえ決まれば直線的に進む。

## 5. 実装の共通事項

どちらのコースも、既存の仕組みにそのまま乗る。

- **コース登録**：`src/data/courseRegistry.ts` に1件足すだけ（コード分岐は増やさない設計）
- **進捗メーター**：`src/data/coverage.ts` はコース種別ごとに表示を出し分ける。
  カタカナ語・漢字とも「会話被覆率%」は意味を成さない規模なので、**ja-kana と同じ「語数のみ」表示**でよい。
  既存の `kana` 種別をそのまま使えば**コード改修ゼロ**。専用の見せ方にしたい場合だけ
  `types.ts` と `coverage.ts` に1ケースずつ追加が要る（小さい）
- **利用者への出し分け**：管理者画面の「使えるコース」割り当てで、必要な人にだけ見せられる。
  コースが 6 → 8 に増えても、メンバーの画面が散らからない
- **語彙データの置き場**：`public/data/courses/<id>/`（他コースと同じ）

## 7. リスクと対策

| リスク | 対策 |
|---|---|
| **カタカナ語が既存コースと重複**（同じ語を2コースで別々に学習・進捗も別々） | 学ぶ技能が違う（意味を覚える vs 速く読む）ので併存自体は妥当。混乱を避けたい人には、管理者画面でどちらか一方だけ割り当てる |
| **漢字カードが重くなり完走率が落ちる** | §4.4 の B-2 を採る。例語は表示のみで採点対象にしない |
| コースが増えて画面が散らかる | 管理者画面のコース割り当てで一人あたり1〜2コースに絞る |
| tanos のリスト内容が想定と違う | 取得時点で字数を確定してから設計を確定する（§4.3 の数字は目安） |
| 訳の品質（タガログ語） | カタカナ語は**既存の訳をそのまま流用**するので新たな品質リスクは無い。漢字の意味は新規生成になるため、メンバーに確認してもらう前提で出す |

---

## 8. 決めてほしいこと

1. **着手するか／順序**（推奨：カタカナ語 → 漢字）
2. **カタカナ語の規模**（推奨：A-2 の約830語。入門重視なら A-1 の約200語）
3. **漢字カードの「覚えた」の定義**（推奨：B-2 意味＋代表読み。例語は表示のみ）
4. コース名（例：`Japanese Katakana Words` / `Japanese Kanji (JLPT N5–N4)`）

1〜3 が決まれば、あとは直線的に進められる。
