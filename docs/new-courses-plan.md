## 2. コースA：カタカナ語（`ja-katakana`）

### 2.1 内容

- **収録**：ja-0-3k と ja-3-10k のカタカナのみの見出し語 **830語**
- **並び順**：元の frequencyRank 順（頻度順）を維持し、通し番号を振り直す
- **カードの中身**：見出し語・読み・グロス・例文とも**既存の値をそのまま流用**（新規生成なし）

### 2.2 実装手順

1. `pipeline/build_ja_katakana.py` を新規作成
   - `public/data/courses/ja-0-3k/words-*.json` と `ja-3-10k/words-*.json` を読む
   - 見出し語が `^[ァ-ヴー]+$` に一致するものを抽出（長音符「ー」を含む・中黒や空白を含む語は対象外）
   - 重複を排除（両コースに同じ語がある場合は頻度が高いほうを残す）
   - frequencyRank を 1 から振り直す
   - `emit_course()` で `public/data/courses/ja-katakana/` に出力
2. `meta.json` の `type` は **`kana` を流用**（進捗メーターのコード改修が要らない。§5.2）
3. `src/data/courseRegistry.ts` に1件追加
4. 出典（`sources`）は**抽出元コースの sources をそのまま引き継ぐ**（JMdict/EDRDG・Tatoeba・tanos・wordfreq）

### 2.3 検証

- 生成後に「カタカナ以外が混ざっていないか」「重複が無いか」「例文の欠落率」を機械チェック
- ブラウザでコースを開き、カードをめくって訳と例文が出ることを目視

## 3. コースB：基本漢字（`ja-kanji-basic`）

### 3.1 収録する字

**JLPT N5＋N4 の漢字**（目安 約284字）。実際の字数は tanos のリスト取得時に確定する。

### 3.2 カードの作り（Kohei 指定：意味＋読み＋使用例をすべて）

| VocabCard の項目 | 入れるもの | 例（山） |
|---|---|---|
| `headword` | 漢字1字 | 山 |
| `reading` | 代表的な訓読み・音読み | やま / サン |
| `gloss` | 意味（タガログ語） | bundok |
| `examples` | その字を使う語（下記） | 山（やま）bundok ／ 火山（かざん）bulkan |
| `jlptLevel` | N5 / N4 | N5 |
| `frequencyRank` | その字を含む語数の多い順 | — |

**`jlptLevel` を入れると Stats タブの JLPT リング・コンプリートバッジがそのまま効く**（既存機能・改修不要）。

### 3.3 ⚠️ 使用例を2語出すには UI 側の対応が要る

**現在の学習画面は `examples[0]` の1件しか表示しない**（`StudyGrid.tsx:179` / `FocusSheet.tsx:60`）。
「使用例をすべて載せたい」という指定を満たすには、次のどちらかを選ぶ：

| 案 | やること | 影響 |
|---|---|---|
| **B-a（推奨）** | 2語を**1件の example にまとめる**<br>text=「山（やま）・火山（かざん）」/ translation=「bundok・bulkan」 | **コード改修ゼロ**。1行に収まるので表示も崩れない |
| B-b | StudyGrid / FocusSheet を「最大2件表示」に改修 | 学習画面のコードに手が入る。カードが縦に伸びる |

**推奨は B-a。** まず B-a で出して、実際に見て物足りなければ B-b に切り替える（データ側は同じなので後から変えられる）。

### 3.4 データ源と取得

| 用途 | データ源 | ライセンス | 備考 |
|---|---|---|---|
| どの字か | tanos.co.uk の JLPT 漢字リスト | CC BY | 語彙リストで**採用済み**。同じ出典表記を流用 |
| 読み（音・訓） | KANJIDIC2 | EDRDG | JMdict と同じ提供元。**採用済み** |
| 意味（タガログ語） | ①既存の単字見出しのグロス → ②無ければ生成 | — | §3.5 |
| 使用例の語 | 既存の ja-0-3k / ja-3-10k | 取得済み | 学習者が実際に出会う語になる |

### 3.5 意味（タガログ語）の作り方 — 二段構え

1. **既存流用**：その漢字が単字の見出し語として存在すれば、そのタガログ語グロスを使う
   （1,077字が該当。基本漢字284字はほぼ常用字なので大半が該当する見込み）
2. **不足分のみ生成**：KANJIDIC2 の英語 meaning を元に、タガログ語訳を LLM バッチで生成
   （コースA・Eのバッチ生成と同じ手順。基本漢字では**多くて100字程度**の見込み）

### 3.6 読みの選び方

KANJIDIC2 は1字に読みを多数持つ（`生` は10以上）。**全部載せると読めないので絞る**：

- **その字の使用例に実際に現れる読みを優先**する（例語から逆引きする）
- 訓読み・音読みを**それぞれ最大2つまで**、`やま / サン` の形式で `reading` に入れる
- 送り仮名は `-` で示す（例：`た-べる`）

### 3.7 使用例の選び方

- その漢字を含む語を既存コースから探し、**頻度が高い順に2語**
- 訓読みの語・音読みの語が**1つずつ選べるなら優先**する（読み分けの学習になる）
- 語には既にタガログ語グロスがあるのでそのまま使う

## 4. コースC：上級漢字（`ja-kanji-advanced`）

### 4.1 収録する字 — 規模の決定が必要

「上級語彙コースから抽出」だが、そのまま全部だと 2,582字（基本を除くと約2,300字）で多すぎる。
**その字を含む語がいくつあるか**で足切りするのが現実的：

| 案 | 足切り | 字数（基本284字を除く概算） | 評価 |
|---|---|---|---|
| C-1 | 30語以上 | 約 **10字＋（既出）**→ 実質 7字 | 少なすぎ |
| **C-2（推奨）** | **10語以上** | 約 **700字** | ja-kana の3倍強。1年かけて完走できる規模 |
| C-3 | 3語以上 | 約 1,500字 | 常用漢字（2,136字）に近い。長期戦になる |
| C-4 | 全部 | 約 2,300字 | 1〜2語にしか出ない字が781字あり費用対効果が悪い |

**推奨は C-2（約700字）。** 「上級」として意味があり、かつ終わりが見える規模。
足りなければ後から C-3 相当を追加コースとして足せる（コース追加は1件登録するだけ）。

### 4.2 カードの作り

**コースB と完全に同じ**（意味＋読み＋使用例）。パイプラインも共通化し、
「どの字を収録するか」のリストだけ差し替える設計にする。

### 4.3 意味の生成量

上位700字のうち既存グロスで賄えるのは概算 **約500字**、**生成が要るのは約200字**。
コースB と合わせても **300字程度**で、コースA（30,000語）のバッチに比べれば小さい。

## 5. 実装の共通事項

### 5.1 ファイル構成

```
pipeline/
  build_ja_katakana.py      新規（コースA）
  build_ja_kanji.py         新規（コースB・C 共通。収録リストを引数で切替）
  kanjidic.py               新規（KANJIDIC2 のパース。読み・英語meaning を返す）
public/data/courses/
  ja-katakana/  ja-kanji-basic/  ja-kanji-advanced/
src/data/courseRegistry.ts  3件追加
```

### 5.2 進捗メーター

`coverage.ts` はコース種別で表示を出し分ける。3コースとも「会話被覆率%」は意味を成さないので、
**`type: "kana"` を流用**すれば「語数のみ」表示になり**コード改修ゼロ**。
専用の見せ方にしたくなったときだけ `types.ts` と `coverage.ts` に1ケースずつ追加する。

### 5.3 利用者への出し分け

コースが 6 → 9 に増えるが、管理者画面の「使えるコース」割り当てで一人あたり1〜2本に絞れる。
**メンバーの画面が散らかる問題は既に解決済み。**

### 5.4 出典表記

- コースA：抽出元の sources をそのまま引き継ぐ
- コースB・C：上記に **KANJIDIC2（EDRDG）** を追加。tanos は既存表記を流用

## 7. リスクと対策

| リスク | 対策 |
|---|---|
| 使用例が1件しか表示されない（§3.3） | まず B-a（2語を1行にまとめる）で出す。物足りなければ UI 改修 |
| 読みを絞りすぎ／載せすぎ | 例語に現れる読みを優先し、訓・音それぞれ最大2つ。実データを見て調整 |
| タガログ語訳の品質 | 既存グロス流用が主（1,077字）。生成分はメンバーに確認してもらう前提（判断ログ#18） |
| カタカナ語が既存コースと重複 | 学ぶ技能が違う（意味 vs 速読）。混乱を避けたい人には管理者画面で片方だけ割り当て |
| 上級漢字が多すぎて完走できない | 10語以上（約700字）で足切り。足りなければ後から追加コースにする |
| KANJIDIC2 が大きい（XML 数十MB） | `pipeline/raw/` に置く（gitignore 済み）。パース結果だけを成果物にする |
